# video-delivery-optimization Specification

# Spec Delta: video-delivery-optimization（视频压缩管线与播放带宽控制）

## Purpose

定义 360° 展示视频的转码压缩规范与前端播放时的带宽控制行为，使外网访客在普通带宽下也能流畅加载与播放视频预览。

## Requirements

### Requirement: 发布前视频统一转码压缩

发布导出管线 MUST 对每个 `V_*.mp4` 进行 ffmpeg 转码：H.264 编码、移除音轨、保持源分辨率不缩放（实测源为 2048×2048 / 1024×1024）、恒定质量压缩（默认档位 `cq 36`，经四档样片实测与 SSIM 评分确认）；转码后的单文件体积应明显下降（默认档位目标：媒体总体积从实测 444MB 降至 200MB 以内），且 360° 预览在网格卡片与详情弹窗尺寸下观感清晰可用（实测 700px 显示尺寸 SSIM ≥ 0.99）。转码需幂等：已符合规范的文件跳过，源文件或转码参数变更才重转。

#### Scenario: 首次执行导出
- **WHEN** 对当前媒体库执行发布导出转码
- **THEN** 全部 mp4 被转码为压缩版本，`static/media` 总体积显著下降，且每个资产的视频仍可正常播放

#### Scenario: 重复执行导出
- **WHEN** 源视频未变化时再次执行导出转码
- **THEN** 已压缩的文件被跳过，不重复转码

### Requirement: 悬停播放并发与视口控制

缩略图模式下，同一时刻实际播放的视频数量 MUST 有上限（默认不超过 3 路）；仅当卡片进入浏览器视口时才允许触发播放相关加载，离开视口的视频 MUST 暂停。

#### Scenario: 快速划过大量卡片
- **WHEN** 访客鼠标快速划过十几个卡片
- **THEN** 实际同时播放的视频不超过上限，页面不因带宽挤占而卡死

#### Scenario: 滚动离开视口
- **WHEN** 一个正在播放视频的卡片被滚动出可视区域
- **THEN** 该视频暂停，不再消耗带宽与解码资源

### Requirement: 视频墙模式受控播放

视频墙模式开启时，SHALL 只对当前视口内（可扩展缓冲区）的可见视频启动播放；不可见视频 MUST NOT 同时加载播放。

#### Scenario: 视频墙模式下浏览
- **WHEN** 访客切换到视频墙模式并滚动页面
- **THEN** 仅视口内的视频处于播放状态，滚动离开的自动暂停，页面滚动与视频加载保持流畅
